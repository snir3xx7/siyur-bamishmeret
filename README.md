# סיור במשמרת

משחק סימולציה אינטראקטיבי בעברית לחניכי קורס יסוד סייר ולמדריכים. המוקד מעביר משימה, השחקן אוסף מידע, מגיע לזירה, משוחח עם דמויות, מקבל החלטות, מעדכן את המוקד – ומסיים בתחקיר ובטיוטת דוח פעולה.

> **סימולציה עצמאית לצורכי תרגול. במצב חירום אמיתי יש לפנות למוקד 100.**
> כל הדמויות, המקומות ואותות הקריאה בדויים.

- חינם, ללא חשבון, פרסומות, מנוי, מפתח API או שירות בתשלום.
- React + TypeScript + Vite, אתר סטטי ל־GitHub Pages, PWA עם עבודה לא מקוונת.
- 13 תרחישים מלאים: תאונה בגשם, רעש בבניין, ויכוח בחצר, קשיש שלא חזר, חפץ חשוד, רכב חוסם, ילד אבוד בשוק, אחרי קטטה (טיפול לאחר האירוע), ריח גז, פריצה לדירה, חשד לגניבה ממינימרקט (קטין), קריאה על חשד לאלימות במשפחה, ורעש ושתייה של בני נוער בגינה. ללא מכניקות מאבק או נשק.
- תחנה ואות קריאה: ברירת מחדל בדויה, או מחוז/תחנה (כפר סבא, נתניה, או הזנה ידנית) – שרשרת קשר משל״ט → משגר → 401 → הניידת.
- נוהל קשר (אישור קבלה, דיווח הגעה, פתיחה/סיום בעדכונים, מענה ל„אתה פנוי?”) – מדד נפרד בתחקיר; פנקס שטח שנבדק בתחקיר; תעבורת קשר של ניידות אחרות; בחירת מסלול לפי משמרת; צופים מצלמים.
- משמרת מלאה (‎#/shift): כמה אירועים ברצף וסיכום משמרת; קישור משמרת לכיתה בעמוד המדריך.
- קריינות מלאה ב־BlueTTS (מקומי וחינמי): כל שורה בקול הדמות, הקשר בקולות 401/משל״ט/קצין תורן עם אפקט מכשיר קשר, ופתיחות שידור לכל תחנה.
- הנגשה: עמוד „איך משחקים”, הנחיית סיבוב לטלפון, מדריך פתיחה, מסך מלא, אזורי מגע גדולים.
- הנפשת דמויות ב־PixiJS (נטען רק בזירה; כבוי בהפחתת תנועה ובבדיקות אוטומטיות, ‎?pixi=1 מפעיל, ‎?nopixi מכבה).
- תחום ניקוד „הפעלת סמכות ונהלים” בתרחישים החדשים: הצגה עצמית, הסבר הסיבה לפני דרישה, הוראה ברורה, אזהרה, עיכוב רק על בסיס עובדתי ווידוא לפני מסירה.
- זירה חיה: התקרבות מצלמה לנקודה שנבחרה, דמויות שמגיבות לשינוי מצב רוח ומסומנות כשהן מדברות, נורית קשר להודעות מוקד, ו**אירועים מתפתחים** – משהו שקורה מעצמו באמצע הזירה ודורש הערכת מצב מחודשת (בתאונה: החמרה במצב המעורב). כל התנועה מכבדת „הפחתת תנועה”.
- איורים חצי־ריאליסטיים מקוריים (רקעים, 11 דמויות במצבי גוף שונים, רכבים) שנוצרו מקומית עם FLUX.1 schnell, ושלטים בעברית כשכבת טקסט. הצלילים נוצרים בקוד. פירוט: [docs/MEDIA.md](docs/MEDIA.md).

## דרישות

- Node.js 20 ומעלה (נבדק עם 24)
- `ffmpeg` – רק אם מפיקים מחדש את קובצי האודיו (`npm run assets`)
- ComfyUI עם `flux1-schnell-fp8` – רק אם מפיקים מחדש את האיורים (`npm run art`)

## התקנה והרצה

```bash
npm install
npm run dev          # שרת פיתוח: http://localhost:5173
```

## בדיקות ובנייה

```bash
npm run lint         # ESLint
npm test             # בדיקות יחידה (Vitest): מנוע, ניקוד, זרעים, שמירות, תקינות תרחישים
npm run build        # בנייה ל-dist/
npm run budget       # תקציב ביצועים: טעינה ראשונית לקטלוג עד 1MB
npx playwright install chromium webkit   # פעם אחת
npm run test:e2e     # בדיקות מקצה לקצה מול ה-build, מוגש בתת-נתיב /siyur-bamishmeret/
npm run test:all     # הכול ברצף
```

`npm run serve:subpath` מגיש את `dist/` בכתובת `http://localhost:4178/siyur-bamishmeret/` – כמו מאגר ב־GitHub Pages.

## פרסום ב־GitHub Pages

הנתיבים בפרויקט יחסיים (`base: './'` וניתוב ב־`#`), כך שאותו build עובד בשורש דומיין ובתת־נתיב של מאגר (`https://<user>.github.io/<repo>/`) בלי שינוי.

1. צרו מאגר **ציבורי** ב־GitHub והעלו את הקוד לענף `main`.
2. ב־**Settings → Pages → Build and deployment → Source** בחרו **GitHub Actions**.
3. כל `push` ל־`main` מריץ את `.github/workflows/deploy.yml`: התקנה, lint, בדיקות יחידה, build, תקציב, בדיקות מקצה לקצה – ופרסום.
4. הכתובת תופיע בלשונית **Actions** ובהגדרות Pages.

## עבודה לא מקוונת (PWA)

- ה־service worker (`public/sw.js`) שומר את מעטפת האפליקציה בביקור הראשון, לפי רשימה שנוצרת ב־build (`precache.json`).
- תמונות ואודיו של תרחיש **לא** נשמרים אוטומטית. בכרטיס התרחיש לוחצים **„הורדת תרחיש לשימוש לא מקוון”**; הסטטוס **„מוכן לשימוש לא מקוון”** מוצג רק אחרי שכל הנכסים נבדקו במטמון.
- אפשר גם „הוספה למסך הבית” (manifest ואייקונים) – אפשרות משלימה, לא חובה.
- ה־service worker פעיל רק ב־build (לא ב־`npm run dev`).

## שמירה ופרטיות

- הגדרות: `localStorage`. ניסיון פעיל והיסטוריה: IndexedDB. מחיקה: עמוד „היסטוריה”.
- אם האחסון חסום (למשל גלישה פרטית) – אפשר להשלים משחק ולייצא תחקיר מהסשן הנוכחי.
- אין טפסי זיהוי, מיקום, מיקרופון או חיבור למערכות חיצוניות.

## הוספת תרחיש

1. העתיקו קובץ מ־`public/scenarios/` ושנו `id`, `version`, כותרת ותוכן.
2. הוסיפו רשומה ל־`public/scenarios/index.json`.
3. הוסיפו מסלול מלא ל־`GOOD_PATHS` ב־`tests/unit/scenarios.test.ts`.
4. `npm test` – בודק הפניות, מסלולים, נכסים וניקוד.

מדריך מלא עם דוגמה מקצה לקצה: [docs/INSTRUCTOR.md](docs/INSTRUCTOR.md). סכימת התרחיש: [docs/SCENARIO_SCHEMA.md](docs/SCENARIO_SCHEMA.md).

## מבנה

```
public/scenarios/   תרחישים (JSON) + index.json
public/img|audio|icons  נכסים מקוריים (נוצרים ב-npm run assets)
public/sw.js        service worker
src/engine/         מנוע: מצב, תנאים, ניקוד, תחקיר, דוח, בדיקת תרחישים
src/scene/          זירה בשכבות, דמויות, רכבים, קטע מעבר
src/audio/          מנוע שמע בערוצים (דיבור, קשר, סביבה, אפקטים)
src/screens/        מסכים: בית, קטלוג, כרטיס, משחק, תחקיר, למדריך, אודות, היסטוריה
src/config/site.ts  טקסטים שקל לעדכן: קרדיטים, הבהרות, קישורי השראה
scripts/            הפקת נכסים, שרת תת-נתיב, תקציב ביצועים
tests/unit|e2e      בדיקות
docs/               סכימה, מדריך למדריך, נכסי מדיה, דוח בדיקות
```
